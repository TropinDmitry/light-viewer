# Light Viewer: ТЗ на прототип

## Зачем
Компания (производитель светильников, сайт diora.pro) планирует переделывать сайт. Нужен **встраиваемый модуль**, который показывает светильник в 3D и даёт примерную картинку того, как он светит. Это прототип: его покажут руководству как аргумент «можем сделать сами».

## Что сделать
1. **Просмотр 3D-модели светильника.**
   - Загрузка GLB/GLTF.
   - Если модели нет, используется процедурная заглушка: линейный светильник, «таблетка», прожектор.
   - Вращение и зум, включение и выключение свечения (эмиссия рассеивателя).
2. **Свет по IES-файлу** (формат IESNA LM-63, фотометрия производителя, обычно её делают для DIALux).
   - Парсер IES: углы, кандела-таблица, множители.
   - Сначала проверить, что есть в Three.js (`IESLoader`, `IESSpotLight` в addons, в том числе ограничения WebGL и WebGPU). Если не подходит, написать свой парсер и своё распределение.
   - Тестовые IES-файлы сгенерировать самим: косинусное (ламбертовское), узкое и широкое распределение. С непроверенных сайтов ничего не скачивать.
3. **Режим «в помещении».**
   - Пресеты комнаты: офис 6×4×3 м, склад, улица.
   - Параметры: высота подвеса, количество светильников (сетка), шаг.
   - Реалистичная картинка в той мере, в какой позволяет браузер: тени, отражения не обязательны.
4. **Карта освещённости.**
   - Цветная карта на полу (рабочей плоскости) в люксах с легендой; минимум, среднее и максимум, равномерность.
   - Расчёт прямой составляющей: `E = I(θ, φ) · cos(угла падения) / d²`, сумма по светильникам.
   - Отражения от стен не учитываются, это нужно явно подписать в интерфейсе как приближение.
5. **Встраиваемость.**
   - Ядро на чистом TS + Three.js без привязки к фреймворку.
   - Сборка как библиотека плюс custom element, например `<luminaire-viewer model="..." ies="..." lumens="...">`.
   - Демостраница на Vite (React + TS) показывает все возможности.

## Проверка
- Unit-тесты (vitest):
  - парсер IES;
  - расчёт освещённости сверяется с ручным расчётом: один светильник с ламбертовским распределением, точка под ним и точка под углом;
  - суммирование по нескольким светильникам.
- Запустить демо в браузерной панели и убедиться, что модель, свет, комната и карта работают. Сделать скриншоты.
- `npm run build` и typecheck без ошибок.

- Git: коммитить локально можно; без строк про Claude в сообщениях коммитов (так пользователь просил в своём другом репозитории). Никуда не пушить и не создавать удалённые репозитории без вопроса.

## Стиль кода
Код должен быть читабельным и «человеческим»: пользователь будет по нему изучать стек.
- Простые, явные конструкции. Без хитрых паттернов: никаких фабрик фабрик, DI, сложных дженериков, метапрограммирования, цепочек reduce/compose там, где хватит обычного цикла.
- Понятные имена переменных и функций, небольшие функции с одной задачей, плоская структура папок.
- Комментарии на русском там, где неочевидно «зачем» (особенно математика освещения, шейдеры, работа с Three.js). Очевидное не комментировать.
- Типы TS простые и явные. React — функциональные компоненты и обычные хуки, без лишних абстракций и state-менеджеров, если они не нужны.
- Если что-то уже написано сложнее — упростить.
- В README — короткий «путеводитель по коду»: с какого файла начать читать.
